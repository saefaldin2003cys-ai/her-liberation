# ربط الباكند — دليل مفصّل

الواجهة تعمل بلا باكند: كل الصفحات تُولَّد ستاتيكياً وتظهر. الباكند يضيف ثلاثة أشياء فقط:

| الخدمة | ماذا تضيف | بدونها |
|---|---|---|
| **MongoDB Atlas** | المقالات، عدّاد المشاهدات، الاستفتاء | المدونة فارغة، العدّادات أصفار |
| **كلمة مرور المدير** | الدخول إلى `/ar/admin` | لا تستطيع النشر |
| **Cloudinary** | رفع الصور داخل المحرّر | زر الصورة يعطي خطأ 501 |

كل واحدة مستقلة. اضبط ما تحتاجه الآن ودع الباقي.

---

## ١. MongoDB Atlas

### ما يحدث فعلياً

الكود لا يتصل بالقاعدة عند إقلاع الخادم، بل عند أول طلب يحتاجها. ثم **يحتفظ بالاتصال** في `globalThis` ويعيد استخدامه.

السبب مهم: الدوال في بيئة serverless تُجمَّد وتُذاب ولا تُغلَق. لو فتحنا اتصالاً جديداً لكل طلب لاستنفدنا حدّ اتصالات Atlas خلال دقائق. انظر `src/lib/mongodb.ts`.

### الخطوات

**أ. اسمح لعنوانك بالوصول** — وهذا سبب تعطّلك الحالي.

Atlas → **Network Access** → **Add IP Address**:

- **Add Current IP Address** — للعمل من جهازك
- ثم أضف **`0.0.0.0/0`** — ضروري لـVercel لأن عناوينها الصادرة غير ثابتة، ولن يتصل الموقع المنشور بدونه

> عنوانك من مزوّد إنترنت منزلي **يتغيّر**. إن عمل الموقع اليوم وتعطّل غداً بخطأ
> `tlsv1 alert internal error` فهذا هو السبب — Atlas يقطع مصافحة TLS للعناوين غير المسموحة، فيظهر الخطأ كأنه مشكلة تشفير لا مشكلة صلاحيات. لهذا `0.0.0.0/0` أريح.

**ب. أنشئ مستخدم قاعدة بيانات**

Atlas → **Database Access** → **Add New Database User**:
- طريقة المصادقة: Password
- الصلاحية: **Read and write to any database** (أو `readWrite` على `herliberation` فقط، وهو أدق)

إن كانت كلمة المرور تحتوي `@ : / ? # %` فيجب ترميزها في الرابط. الأسهل: اختر كلمة مرور بأحرف وأرقام فقط.

**ج. خذ رابط الاتصال**

Atlas → **Connect** → **Drivers** → Node.js → انسخ الرابط، ثم ضعه في `web/.env.local`:

```
MONGODB_URI=mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
MONGODB_DB=herliberation
```

اسم القاعدة منفصل في `MONGODB_DB`، فلا حاجة لوضعه داخل الرابط.

**د. تحقق**

```bash
npm run db:check
```

يفحص الـDNS ثم الاتصال ثم المصادقة ثم القراءة، ويقول أيّ خطوة فشلت تحديداً — لأن «فشل الاتصال» وحدها لا تدلّ على شيء.

**هـ. رحّل بياناتك القديمة** (مرة واحدة)

```bash
npm run db:migrate -- --dry   # معاينة بلا تغيير
npm run db:migrate            # تطبيق
```

بيانات Mongoose القديمة أشكالها مختلفة: `timestamp` بدل `createdAt`، و`image` بدل `coverImage`، والمحتوى نص عادي لا HTML. السكربت يوائمها، وهو **غير مدمّر ويمكن تكراره** — يضيف الحقول الجديدة ويترك القديمة.

وينقل الاستفتاء إلى الشكل الجديد **بلا عناوين IP**: الموقع القديم كان يخزّن IP كل مصوّت نصاً صريحاً وللأبد. على موقع يخصّ فئة هشّة، سجلّ بمن أبدى رأياً في زواج القاصرات مسؤولية لا ميزة. الكود الجديد يحفظ hash مملّحاً فقط.

### إن تعطّل الـSRV

بعض الشبكات تجيب استعلامات SRV بتقطّع، وشبكتك إحداها. الكود يعيد المحاولة تلقائياً عبر DNS عام، وإن استمرّ:

```bash
npm run db:direct
```

يولّد رابطاً بلا SRV يسرد المضيفات صراحةً. استخدمه محلياً، وأبقِ `mongodb+srv` لـVercel.

## ٢. كلمة مرور المدير

### لماذا لا يوجد جدول مستخدمين

هناك مدير واحد. فالبيانات الوحيدة المخزّنة هي **hash** لكلمة المرور في متغيّر بيئة، والجلسة **كوكي موقّع httpOnly** لا تستطيع الجافاسكربت قراءته.

الموقع القديم كان يضع كلمة المرور نصاً صريحاً في `script.js` وفي `README` — أي أن أي زائر يفتح مصدر الصفحة يراها.

### اضبطها

كلمة المرور الحالية انتقلت من المشروع القديم ولا نعرفها. اضبط واحدة:

```bash
npm run set-password
```

يسأل عن كلمة المرور (الكتابة مخفية)، يحسب الـhash، ويكتبه في `.env.local`. كلمة المرور نفسها لا تُطبع ولا تُخزَّن.

ثم أعد تشغيل الخادم وادخل على `/ar/admin`.

> على Vercel ضع **الـhash** لا كلمة المرور. السكربت يطبعه لك في النهاية.

## ٣. Cloudinary — رفع الصور

### لماذا لا نكتب على القرص

`/api/upload` القديم كان يكتب في `public/uploads`. هذا **يفقد كل الصور مع كل إعادة نشر** — قرص التطبيق المستضاف مؤقت. كان معطّلاً فعلياً على Render.

### الخطوات

1. سجّل في [cloudinary.com](https://cloudinary.com) — الطبقة المجانية سخية
2. من **Dashboard** انسخ: Cloud name، API Key، API Secret
3. ضعها في `.env.local`:

```
CLOUDINARY_CLOUD_NAME=xxxxx
CLOUDINARY_API_KEY=xxxxx
CLOUDINARY_API_SECRET=xxxxx
```

4. أعد تشغيل الخادم

الرفع يقبل JPEG/PNG/WebP/AVIF حتى 8MB، و**يتطلب جلسة مدير** — لا يستطيع زائر الرفع.

`next.config.ts` يسمح مسبقاً بـ`res.cloudinary.com` في `images.remotePatterns`، فالصور المرفوعة تمرّ عبر تحسين صور Next تلقائياً.

بدونها المحرّر يعمل كاملاً عدا زر إدراج الصورة، ويعطي رسالة واضحة بدل الانهيار.

## ٤. التحقق من كل شيء

```bash
npm run dev      # في نافذة
npm run verify   # في أخرى
```

الفحص **لا يكتفي بكود 200**: يتأكد أن كل صفحة تحتوي نصّها الخاص، لأن صفحة تعرض رسالة خطأ تُرجع 200 أيضاً. ويتحقق من: المتغيّرات، القاعدة، ١١ صفحة بلغتين، غياب الإيموجي وصور الـAI، صحة `dir`، اكتمال الترجمة، الـAPI، وأن الكتابة بلا جلسة مرفوضة.

## ٥. النشر على Vercel

1. ارفع المستودع إلى GitHub
2. [vercel.com](https://vercel.com) → **Add New Project** → اختر المستودع
3. **Root Directory: `web`** — مهم، فالمشروع في مجلد فرعي
4. **Environment Variables** — أضف نفس مفاتيح `.env.local`:

| المفتاح | ملاحظة |
|---|---|
| `MONGODB_URI` | استخدم صيغة `mongodb+srv` هنا |
| `MONGODB_DB` | `herliberation` |
| `AUTH_SECRET` | ولّد واحداً جديداً للإنتاج، لا تعد استخدام المحلي |
| `ADMIN_PASSWORD_HASH` | الـhash لا كلمة المرور |
| `CLOUDINARY_*` | الثلاثة |
| `NEXT_PUBLIC_SITE_URL` | `https://your-domain.com` |

5. **Deploy**

### ربط نطاق Cloudflare

Vercel → Project → **Settings** → **Domains** → أضف نطاقك، وسيعطيك سجلات DNS.

في Cloudflare → **DNS**:

| النوع | الاسم | القيمة | Proxy |
|---|---|---|---|
| CNAME | `www` | `cname.vercel-dns.com` | **DNS only** (سحابة رمادية) |
| A | `@` | العنوان الذي يعطيه Vercel | **DNS only** |

> اجعله **DNS only** لا Proxied. تفعيل بروكسي Cloudflare فوق Vercel يضيف طبقة CDN ثانية تُربك إصدار شهادة TLS وتخزين ISR. Vercel يوفّر الـCDN والشهادة أصلاً.

بعد ربط النطاق حدّث `NEXT_PUBLIC_SITE_URL` وأعد النشر ليصحّ الـcanonical وOpen Graph.

## ما بقي

- **مفاتيح Cloudinary** — رفع الصور معطّل حتى تُضاف
- **`0.0.0.0/0` في Atlas** — بدونه لن يتصل الموقع المنشور
- **مصدر أرقام المحافظات الخمس** — مكتوب حالياً «بيانات الحملة». إن كان لها مصدر حقيقي (مسح MICS مثلاً) ضعه في `src/data/provinces.ts`؛ الخريطة تعرض المصدر لكل محافظة صراحةً
