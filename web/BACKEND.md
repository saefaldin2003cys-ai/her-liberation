# ربط الباكند — دليل مفصّل

الواجهة تعمل بلا باكند: كل الصفحات تُولَّد ستاتيكياً وتظهر. الباكند يضيف ثلاثة أشياء فقط:

| الخدمة | ماذا تضيف | بدونها |
|---|---|---|
| **MongoDB Atlas** | المقالات، عدّاد المشاهدات، الاستفتاء | المدونة فارغة، العدّادات أصفار |
| **كلمة مرور المدير** | الدخول إلى `/ar/admin` | لا تستطيع النشر |
| **Cloudinary** | رفع الصور داخل المحرّر | زر الصورة يعطي خطأ 501 |

كل واحدة مستقلة. اضبط ما تحتاجه الآن ودع الباقي.

---

## ١. MongoDB Atlas

### ما يحدث فعلياً

الكود لا يتصل بالقاعدة عند إقلاع الخادم، بل عند أول طلب يحتاجها. ثم **يحتفظ بالاتصال** في `globalThis` ويعيد استخدامه.

السبب مهم: الدوال في بيئة serverless تُجمَّد وتُذاب ولا تُغلَق. لو فتحنا اتصالاً جديداً لكل طلب لاستنفدنا حدّ اتصالات Atlas خلال دقائق. انظر `src/lib/mongodb.ts`.

### الخطوات

**أ. اسمح لعنوانك بالوصول** — وهذا سبب تعطّلك الحالي.

Atlas → **Network Access** → **Add IP Address**:

- **Add Current IP Address** — للعمل من جهازك
- ثم أضف **`0.0.0.0/0`** — ضروري لـVercel لأن عناوينها الصادرة غير ثابتة، ولن يتصل الموقع المنشور بدونه

> عنوانك من مزوّد إنترنت منزلي **يتغيّر**. إن عمل الموقع اليوم وتعطّل غداً بخطأ
> `tlsv1 alert internal error` فهذا هو السبب — Atlas يقطع مصافحة TLS للعناوين غير المسموحة، فيظهر الخطأ كأنه مشكلة تشفير لا مشكلة صلاحيات. لهذا `0.0.0.0/0` أريح.

**ب. أنشئ مستخدم قاعدة بيانات**

Atlas → **Database Access** → **Add New Database User**:
- طريقة المصادقة: Password
- الصلاحية: **Read and write to any database** (أو `readWrite` على `herliberation` فقط، وهو أدق)

إن كانت كلمة المرور تحتوي `@ : / ? # %` فيجب ترميزها في الرابط. الأسهل: اختر كلمة مرور بأحرف وأرقام فقط.

**ج. خذ رابط الاتصال**

Atlas → **Connect** → **Drivers** → Node.js → انسخ الرابط، ثم ضعه في `web/.env.local`:

```
MONGODB_URI=mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
MONGODB_DB=herliberation
```

اسم القاعدة منفصل في `MONGODB_DB`، فلا حاجة لوضعه داخل الرابط.

**د. تحقق**

```bash
npm run db:check
```

يفحص الـDNS ثم الاتصال ثم المصادقة ثم القراءة، ويقول أيّ خطوة فشلت تحديداً — لأن «فشل الاتصال» وحدها لا تدلّ على شيء.

**هـ. رحّل بياناتك القديمة** (مرة واحدة)

```bash
npm run db:migrate -- --dry   # معاينة بلا تغيير
npm run db:migrate            # تطبيق
```

بيانات Mongoose القديمة أشكالها مختلفة: `timestamp` بدل `createdAt`، و`image` بدل `coverImage`، والمحتوى نص عادي لا HTML. السكربت يوائمها، وهو **غير مدمّر ويمكن تكراره** — يضيف الحقول الجديدة ويترك القديمة.

وينقل الاستفتاء إلى الشكل الجديد **بلا عناوين IP**: الموقع القديم كان يخزّن IP كل مصوّت نصاً صريحاً وللأبد. على موقع يخصّ فئة هشّة، سجلّ بمن أبدى رأياً في زواج القاصرات مسؤولية لا ميزة. الكود الجديد يحفظ hash مملّحاً فقط.

### إن تعطّل الـSRV

بعض الشبكات تجيب استعلامات SRV بتقطّع، وشبكتك إحداها. الكود يعيد المحاولة تلقائياً عبر DNS عام، وإن استمرّ:

```bash
npm run db:direct
```

يولّد رابطاً بلا SRV يسرد المضيفات صراحةً. استخدمه محلياً، وأبقِ `mongodb+srv` لـVercel.

## ٢. كلمة مرور المدير

### لماذا لا يوجد جدول مستخدمين

هناك مدير واحد. فالبيانات الوحيدة المخزّنة هي **hash** لكلمة المرور في متغيّر بيئة، والجلسة **كوكي موقّع httpOnly** لا تستطيع الجافاسكربت قراءته.

الموقع القديم كان يضع كلمة المرور نصاً صريحاً في `script.js` وفي `README` — أي أن أي زائر يفتح مصدر الصفحة يراها.

### اضبطها

كلمة المرور الحالية انتقلت من المشروع القديم ولا نعرفها. اضبط واحدة:

```bash
npm run set-password
```

يسأل عن كلمة المرور (الكتابة مخفية)، يحسب الـhash، ويكتبه في `.env.local`. كلمة المرور نفسها لا تُطبع ولا تُخزَّن.

ثم أعد تشغيل الخادم وادخل على `/ar/admin`.

> على Vercel ضع **الـhash** لا كلمة المرور. السكربت يطبعه لك في النهاية.

## ٣. Cloudinary — رفع الصور

### لماذا لا نكتب على القرص

`/api/upload` القديم كان يكتب في `public/uploads`. هذا **يفقد كل الصور مع كل إعادة نشر** — قرص التطبيق المستضاف مؤقت. كان معطّلاً فعلياً على Render.

### الخطوات

1. سجّل في [cloudinary.com](https://cloudinary.com) — الطبقة المجانية سخية
2. من **Dashboard** انسخ: Cloud name، API Key، API Secret
3. ضعها في `.env.local`:

```
CLOUDINARY_CLOUD_NAME=xxxxx
CLOUDINARY_API_KEY=xxxxx
CLOUDINARY_API_SECRET=xxxxx
```

4. أعد تشغيل الخادم

الرفع يقبل JPEG/PNG/WebP/AVIF حتى 8MB، و**يتطلب جلسة مدير** — لا يستطيع زائر الرفع.

`next.config.ts` يسمح مسبقاً بـ`res.cloudinary.com` في `images.remotePatterns`، فالصور المرفوعة تمرّ عبر تحسين صور Next تلقائياً.

بدونها المحرّر يعمل كاملاً عدا زر إدراج الصورة، ويعطي رسالة واضحة بدل الانهيار.

## ٤. التحقق من كل شيء

```bash
npm run dev      # في نافذة
npm run verify   # في أخرى
```

الفحص **لا يكتفي بكود 200**: يتأكد أن كل صفحة تحتوي نصّها الخاص، لأن صفحة تعرض رسالة خطأ تُرجع 200 أيضاً. ويتحقق من: المتغيّرات، القاعدة، ١١ صفحة بلغتين، غياب الإيموجي وصور الـAI، صحة `dir`، اكتمال الترجمة، الـAPI، وأن الكتابة بلا جلسة مرفوضة.

## ٥. النشر على Vercel

الموقع القديم يبقى على `www.her-liberation.org`، والجديد يعيش على عنوان Vercel حتى تقرّر التبديل. الاثنان يعملان معاً، **ويتشاركان قاعدة البيانات نفسها**.

> مقال تنشره من لوحة الجديد يدخل القاعدة نفسها التي يقرأ منها القديم. هذا مقصود — لا تنقسم بياناتك — لكن انتبه أن عدّاد المشاهدات والاستفتاء مشتركان أيضاً، فالأرقام مجموع الموقعين.

### أ. المستودع

الكود في مجلد فرعي، وهذه أهم نقطة في الإعداد كلّه.

1. [vercel.com](https://vercel.com) → **Add New** → **Project**
2. اختر مستودع `her-liberation`
3. **Root Directory** → **Edit** → اختر **`web`**

بدون هذه الخطوة يبحث Vercel عن `package.json` في جذر المستودع فلا يجده، ويفشل البناء برسالة لا تشير إلى السبب. الباقي يكتشفه وحده: Framework = Next.js، الأمر `next build`، المخرجات `.next`.

4. **Production Branch** → `rebuild/next-app` ما دام لم يُدمج في `main`

### ب. المتغيّرات

في **Environment Variables** يقبل Vercel لصق كتلة `.env` كاملة — الصق الستة دفعة واحدة.

| المفتاح | القيمة |
|---|---|
| `MONGODB_URI` | **صيغة `mongodb+srv` حصراً** — انظر التحذير أدناه |
| `MONGODB_DB` | `herliberation` |
| `AUTH_SECRET` | **ولّد واحداً جديداً**: `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"` |
| `ADMIN_PASSWORD_HASH` | الـhash لا كلمة المرور. `npm run set-password` يطبعه |
| `NEXT_PUBLIC_SITE_URL` | عنوان Vercel. لن تعرفه قبل أول نشر — انشر، خذ العنوان، ضعه، أعد النشر |
| `NEXT_PUBLIC_ALLOW_INDEXING` | **`0`** ما دام القديم على النطاق |
| `CLOUDINARY_*` | الثلاثة، حين تفتح الحساب |

> **لا تضع الرابط المباشر `mongodb://` على Vercel.**
>
> `npm run db:direct` يولّد رابطاً يسرد عقد العنقود صراحةً — `ac-xxxx-shard-00-00...`. وُجد لسبب واحد: شبكتك المحلية تجيب استعلامات SRV بتقطّع. لكن Atlas يغيّر أسماء هذه العقد عند ترقية الطبقة أو نقل المنطقة، فالرابط يصلح اليوم وينكسر بعد أشهر بخطأ DNS لا يدلّ على سببه.
>
> `mongodb+srv` يتتبّع العنقود مهما تحرّك. أبقِ المباشر محلياً وحده. صيغة SRV محفوظة كتعليق في `.env.local` على سطر `# MONGODB_URI_SRV=`.

ثم **Deploy**. البناء دقيقتان تقريباً.

### ج. لماذا `ALLOW_INDEXING=0` ليس تفصيلاً

نسخة ثانية من النصوص العربية نفسها على عنوان `*.vercel.app` هي **محتوى مزدوج ينافس موقعك الحيّ** في نتائج البحث. وقد يفوز العنوان الجديد أحياناً، فيصل الزوار إلى نسخة تجريبية بدل موقعك.

الافتراض في الكود هو **المنع**، لأن الخطأين غير متماثلين: نسيان التفعيل يكلّفك إعادة نشر، ونسيان المنع يُدخل نسخة تجريبية إلى فهرس جوجل ويستغرق إخراجها أسابيع.

الإشارتان تُضبطان من المفتاح نفسه — `robots.txt` يمنع الزحف من أصله، ووسم `noindex` في رأس الصفحة يمنع الفهرسة لو وصل الزاحف رغم ذلك. `npm run verify` يتحقق أنهما **متفقتان**، لأن تعارضهما هو العطل الذي يحدث فعلاً وهو صامت.

### د. Atlas

`0.0.0.0/0` في **Network Access** ليس اختياراً هنا: عناوين Vercel الصادرة غير ثابتة، ولا قائمة لها لتضعها. بدونه ينجح البناء ويظهر الموقع، ثم تكون المدونة فارغة والعدّادات أصفاراً — لأن الصفحات تُبنى بلا قاعدة ولا ترمي خطأً.

القاعدة محميّة بالمصادقة لا بالـIP. اجعل مستخدم القاعدة `readWrite` على `herliberation` وحدها لا "any database".

### هـ. تحقّق من الموقع المنشور

```bash
npm run verify -- https://your-project.vercel.app
```

نفس فحوص الصفحات والـAPI، على المنشور بدل المحلي، مع فحص الفهرسة. فحوص `.env.local` تُتخطّى — ملفك المحلي لا يقول شيئاً عمّا أعطيتَه لـVercel.

ثم افتح `/ar/admin` وسجّل الدخول. إن رُفضت كلمة المرور فـ`ADMIN_PASSWORD_HASH` لم يُنسخ كاملاً — الـhash يحتوي `$` وبعض الصدفات تبتلعها عند النسخ من سطر أوامر.

## ٦. حين تقرّر التبديل

لا تفعل شيئاً من هذا قبل أن ترضى عن الجديد. ثم، بالترتيب:

**١. نطاق تجريبي أولاً** (اختياري لكنه يستحق)

في Cloudflare → **DNS** أضف:

| النوع | الاسم | القيمة | Proxy |
|---|---|---|---|
| CNAME | `beta` | `cname.vercel-dns.com` | **DNS only** ☁️ رمادية |

وفي Vercel → Settings → Domains أضف `beta.her-liberation.org`. تختبر على نطاقك الحقيقي بشهادة حقيقية، والموقع الحيّ لم يُمَس. أبقِ `ALLOW_INDEXING=0`.

**٢. التبديل الفعلي**

في Vercel → Settings → **Domains** أضف `her-liberation.org` و`www.her-liberation.org`. سيعطيك سجلّين. في Cloudflare بدّل السجلات الحالية إلى:

| النوع | الاسم | القيمة | Proxy |
|---|---|---|---|
| A | `@` | العنوان الذي يعطيه Vercel | **DNS only** ☁️ رمادية |
| CNAME | `www` | `cname.vercel-dns.com` | **DNS only** ☁️ رمادية |

> السحابة **رمادية لا برتقالية**. نطاقك الآن **برتقالي** — الطلبات تمرّ عبر بروكسي Cloudflare، وهذا ما يخدم القديم. فوق Vercel تصير طبقة CDN فوق طبقة CDN: Vercel يعجز عن التحقق من ملكية النطاق لإصدار شهادة TLS، وتخزين ISR يتعطّل، والزوار يرون شهادة Cloudflare لا شهادتك. Vercel يوفّر الـCDN والشهادة أصلاً.

**٣. بعد أن يتحقق النطاق**

- `NEXT_PUBLIC_SITE_URL` → `https://www.her-liberation.org`
- `NEXT_PUBLIC_ALLOW_INDEXING` → `1`
- أعد النشر، وإلا بقيت روابط canonical وبطاقات المشاركة تشير إلى عنوان Vercel والموقع ممنوعاً من الفهرسة

**٤. لا تهدم القديم فوراً.** أبقِ استضافته أسبوعاً على الأقل. إن ظهر عطل لم يُكتشف، إعادة السجلات إلى ما كانت أسرع من إصلاحه تحت الضغط.

## ما بقي

- **مفاتيح Cloudinary** — رفع الصور معطّل حتى تُضاف
- **`0.0.0.0/0` في Atlas** — بدونه لن يتصل الموقع المنشور
- **مصدر أرقام المحافظات الخمس** — مكتوب حالياً «بيانات الحملة». إن كان لها مصدر حقيقي (مسح MICS مثلاً) ضعه في `src/data/provinces.ts`؛ الخريطة تعرض المصدر لكل محافظة صراحةً
